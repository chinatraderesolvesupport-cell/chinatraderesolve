# Подбор поставщиков — первый рабочий модуль

Статус: отдельная ветка для проверки, без объединения с main и без публикации. Это первый рабочий поток ручного исполнения услуги; не автоматический поисковик.

## Реализовано
- Три типа задания: поиск, проверка, подготовка сделки.
- Поиск с фото, неизвестным названием и запросом альтернатив; зависимая валидация на клиенте и сервере.
- Заявка и до пяти реальных фотографий сохраняются в отдельных sourcing-таблицах. Файлы проходят существующую проверку формата/декодирования и очистку метаданных. По 8 МБ, суммарно 25 МБ; общий multipart-запрос ограничен 26 МБ.
- Персональный просмотр по сессии; восстановление доступа через номер и секретный код, отправляемый POST, не через URL. Код хранится в БД как SHA-256; клиенту необходимо его сохранить. Администратор видит заявки через существующий вход.
- Повторная отправка одной формы создаёт одну заявку, разные вкладки поддерживаются. Состояния, CSRF, блокировка устаревшего обновления, история действий.
- Оператор сохраняет приватный черновик и выдаёт отчёт с источниками, выводами, рисками и следующими шагами после явного подтверждения проверки. Клиент не видит черновик. Выданные версии не перезаписываются; для исправления можно вернуть работу на оценку и выдать новую версию.
- Клиент может удалить заявку, фото, отчёты и события одним подтверждённым действием. Резервные копии хранилища имеют отдельную политику удаления, которую требуется настроить при размещении.

## Не реализовано / не обещать посетителю
Автоматический поиск и распознавание товара, генерация отчёта ИИ на сервере, рассылка, платёжный провайдер, предложения с фиксированной ценой и акцептом, договорная модель, фоновая очередь исследований, несколько операторских ролей, постоянная база доказательств по поставщикам. Нет публичного тестового адреса. Русскоязычный пилот, переводы интерфейса не добавлены.

Текущий оператор вручную исследует сведения и заполняет отчёт. Отправка заявки не является оплатой или договором о платной услуге. Образцы и черновики из предыдущих версий сохранены отдельно; этот модуль не подменяет реальное исследование демонстрационными результатами.

## Размещение и совместимость
Используется FastAPI текущего China Trade, существующая сессия администратора, CSRF и функция обработки файлов. В main.py только установка маршрутов до существующих ASGI-обёрток и лимит тела нового endpoint. Главная, навигация, бесплатные дела, уведомления и существующие таблицы не меняются.

`ENABLE_SOURCING_PILOT` по умолчанию выключен. Новые маршруты возвращают 404, sourcing-таблицы не создаются при выключенном флаге. Флаг задаётся до запуска процесса; включение требует перезапуска. Нельзя включать его на production для проверки этой ветки.

При первом включении создаются четыре новые таблицы: sourcing_requests, sourcing_photos, sourcing_reports, sourcing_events. SQLite используется в изолированных тестах; SQL рассчитан также на PostgreSQL через текущий db-адаптер, но отдельный прогон на PostgreSQL ещё необходим. Фотографии хранятся в БД; для будущих объёмов предусмотреть приватное объектное хранилище за теми же проверками доступа. Не подключать production DATABASE_URL к тестовой копии.

Адреса внутри изолированного приложения: `/sourcing`, `/sourcing/access`, `/admin/sourcing`. Внешний тестовый URL необходимо отдельно создать после CI; ссылка на локальный HTML для испытания рабочей услуги не подходит.

## Проверки
Локально: серверный путь с настоящим multipart JPEG, создание, защита доступа, восстановление, очередь, смена статуса, сохранение черновика, выдача отчёта, экранирование HTML, контроль версий, удаление и каскады. Проверены неправильный email, отсутствие полей/согласия, пустое описание, фото без названия, неверные файлы, размер, количество, лишние поля другой услуги и отключение направления. Включены существующие серверные регрессии.

Добавлен браузерный тест для мобильного клиента и администратора в существующую CI-схему. Локально браузерная QA не запускалась: в среде нет доступного control-browser. Не считать визуальную приёмку завершённой до результата CI и просмотра.

## До публичного запуска
1. CI, включая браузерный сценарий; отдельный PostgreSQL-прогон; визуальная приёмка на телефоне/компьютере.
2. Отдельная тестовая среда и тест от фотографии до реального отчёта оператором.
3. Условия услуги/обработка данных/периоды хранения, автоматическое удаление по сроку и резервные копии; безопасная доставка/восстановление доступа для клиента.
4. Фиксированное предложение с версией задания, границами работ, ценой и правилами отмены. Затем платёжные уведомления, возвраты, сверка.
5. Только после приёмки — отдельное решение об объединении. Откат: выключить флаг; аддитивные таблицы не удалять автоматически.

## Результат текущей проверки
Локально прошли 387 тестов (без tests/test_application_e2e.py), compileall, Node syntax check и pip check. Браузерный сценарий запускается в CI отдельной ветки. Публикация в рабочую среду и объединение с main не выполняются.
